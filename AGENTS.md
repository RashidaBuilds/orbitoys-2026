# ORBITOYS — Agent & Engineering Guidelines

## Code Quality & Architecture Rules

1. **Keep Code Simple, Clean, and Maintainable**: Write straightforward Vanilla JavaScript, HTML, and CSS that is easy to read, debug, and extend.
2. **Inspect Before Creating**: Always inspect existing files, directories, and assets before creating new ones.
3. **Avoid Unnecessary Complexity**: Do not introduce unnecessary files, folders, components, abstractions, or third-party dependencies (no React, Phaser, Rive, or heavy frameworks).
4. **Reuse Existing Assets and Code**: Always reuse the Figma-exported assets in `public/assets/` and shared styles/utilities rather than creating duplicates.
5. **No Duplicate Functionality**: Consolidate shared logic and UI patterns in one place.
6. **Build Only What the MVP Requires**: Stay strictly focused on the ORBITOYS MVP screens and interactions defined in `DESIGN.md`.

## Historical Accuracy & Storytelling Rules

7. **Never Invent Historical Facts or Quotations**: Do not fabricate NASA mission data, dates, engineering specifications, or astronaut quotations.
8. **Distinguish Fiction from Fact**: Clearly separate the fictional toy-store framing narrative (the Shopkeeper and Girl conversation) from historical NASA facts and mission documentation recorded in `SOURCES.md`.

## Workflow & Reporting Rules

9. **Report Changes Clearly**: After every task, explicitly report all files created or modified.
